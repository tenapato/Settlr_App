01 · HIERARCHY

Total first, goals second

The root answers “how much have I saved?” before asking the user to evaluate progress. Goal cards earn more visual weight than flexible pots.

02 · OPTIONAL TARGETS

Accounts do not become fake goals

An account with no target amount stays in Flexible savings. Adding a target promotes it into Your goals without changing the underlying account or transaction history.

03 · STATE LANGUAGE

Progress is explicit

Not started, In progress, and Funded are server-derived. Amount remaining is shown beside progress so color is never the only status cue.

04 · DETAIL FLOW

Tap pushes into the account

Account detail owns its entries, target editing, recurring contribution settings, and archive action. The root stays scannable.

Current API binding: targetAmountCents + targetDate drive goal placement; goalStatus, progressPct, and remainingCents render directly from the Worker response. No client-side financial math is needed.
